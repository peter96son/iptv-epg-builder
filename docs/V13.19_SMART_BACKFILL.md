# v13.19 — Smart Metadata Backfill

## What changed

The metadata database now maintains itself nightly instead of requiring a manual
Backfill Movie Metadata run.

Schedule:
- every day at 11:20 UTC
- approximately 04:20 PDT / 03:20 PST

## Smarter queue

Backfill no longer works mainly alphabetically.

Priority is now:

1. `partial` — identity already known, missing overview/genres;
2. `unknown` — never resolved before;
3. `retryable` — old negative cache whose retry delay expired.

Within those classes it prefers:

- movie/cinema groups;
- programmes still coming up in the current EPG;
- titles appearing many times in the EPG;
- titles appearing on several channels;
- lower prior miss counts.

Fresh `not_found` results are not retried until their negative-cache policy expires.

## Adaptive HTTP budget

5000 remains a hard maximum, not a mandatory spend.

Backlog:
- >10,000 -> up to 5000
- 5,001–10,000 -> up to 3500
- 2,001–5,000 -> up to 2500
- 501–2,000 -> up to 1200
- 101–500 -> up to 500
- 1–100 -> up to 250
- 0 -> no TMDb calls

## Growth statistics

Each run writes:
- `output/metadata-backfill.json`
- `output/metadata-growth-history.json`

The report records before/after:
- movies
- series
- total canonical titles
- IMDb entities
- aliases
- people / credits
- complete metadata
- remaining backfill queue

History retains the latest 180 runs.

## Persistence

The existing architecture is unchanged:
1. restore `.cache`;
2. restore durable `data/metadata.sqlite3.gz`;
3. smart backfill;
4. save durable snapshot;
5. commit the new snapshot and reports with race-safe fetch/rebase/push.

The database is never intentionally reset.
