# v13.13 — UHF archive retention repair

## Problem confirmed
The provider playlist advertises a 5-day Flussonic catch-up/DVR window, but
`XMLTVSource.fresh_programmes()` retained only `past_days=2`. UHF therefore
could not receive enough past programme rows to expose the full provider archive.

## Changes
- `src/xmltv.py`
  - default past programme retention is now 5 days;
  - override with `XMLTV_ARCHIVE_PAST_DAYS` if needed;
  - source eligibility/freshness logic is unchanged.
- `data/channel_time_offsets.csv`
  - CPS USSR +14h is disabled. The hypothesis was disproved by a later live
    observation and must not be applied as a permanent offset.
- `tests/test_archive_retention_v1313.py`
  - 4-day-old programme retained;
  - 6-day-old programme rejected;
  - explicit shorter override remains supported.

## Expected result
After the next Update EPG, if an upstream EPG source itself supplies five days
of historical schedule, the generated XMLTV will retain those rows so UHF can
map them to the provider's catch-up archive.

Important: this cannot manufacture history that the selected upstream EPG source
does not provide. The output can retain up to five days only when the source
actually contains them.
