# EPG Decision Log

Цель: прекратить круговые исправления. Перед любым изменением movie-EPG recovery этот файл обязателен к чтению.

## Базовые состояния канала

1. Есть подтвержденная корректная программа.
2. Есть программа, но она неверная. Это НЕ 3A.
3. Программы нет:
   - 3A: на экране есть название текущего фильма/передачи.
   - 3B: на экране нет пригодного названия.

## Неприкосновенные правила

- 3A работает только если реально нет текущей программы.
- 3A никогда не перезаписывает существующую текущую программу.
- OCR в 3A дает только текущий фильм. Полное расписание ищется отдельно, вторым этапом.
- Для LIVE_OCR не надо выдумывать следующую передачу.
- Одна OCR-строка не является доказательством.
- Высокая уверенность OCR должна требовать независимого подтверждения или совпадения с уже подтвержденным предыдущим названием.
- Внутренний score ранжирует кандидатов, но сам по себе не доказывает правильность текста.
- Логотипы, название канала и статическая графика не считаются названием фильма.
- Первое наблюдение создает PENDING, а не карантин.
- Автоматический донор требует минимум два разных подтвержденных названия фильма.
- Повтор того же фильма в другой час не является вторым независимым доказательством.
- Pending evidence не уничтожает существующий донор.
- Карантин существующего донора возможен только при прямом противоречии именно этому донору.
- Нельзя сообщать об улучшении без измеренного before/after на реальном workflow.

## Зафиксированные ошибки

### 2026-09-12: 3A записал фильм, но аудит не засчитал канал
Факт: `Кино и Жизнь -> Грязные деньги` был записан в XMLTV.
Ошибка: аудитор оставлял `NO_NEXT_PROGRAMME`.
Решение: LIVE_OCR-current считается восстановленным текущим EPG без фиктивного NEXT.

### 2026-09-12: ложный HIGH OCR
Реальный запуск 34707389868:
- `Premiere HD 2 -> РЕЕМТЕВЕ [1`
- `YOSSO-4K -> @уоззок`
были ошибочно помечены HIGH.
Корневая причина: HIGH вычислялся из score одной строки.
Решение: отделить рейтинг от доказательства; одна строка не может быть HIGH.

### 2026-09-12: повторное наращивание IMDb в title
Симптом: `Своя в доску (2026) · IMDb 4.7 (2026) · IMDb 4.7 ...`
Причина: финализатор брал уже измененный title и снова дописывал `(год) · IMDb`.
Решение: metadata title должен быть идемпотентным и ремонтировать уже накопившиеся суффиксы.

### 2026-09-12: живые проверки USSR
- `USSR HD`: в эфире `Следствие ведут знатоки`, текущий EPG показывал `Асса` -> существующий донор противоречит эфиру.
- `YOSSO TV Советские фильмы`: в эфире `Вертикаль`, текущей программы нет.
- `DITV КОМЕДИИ СССР`: название фильма отображается слева; OCR обязан проверять DITV-специфические left-bottom зоны.
- `MM USSR Детектив HD`: заголовки вида `х/ф Визит к Минотавру 3`; служебный префикс `х/ф` не должен ломать сравнение.

## Обязательная процедура любого следующего изменения

1. Найти конкретное нарушенное правило в реальном run/log.
2. Проверить этот Decision Log.
3. Исправить корневую причину.
4. Добавить regression test.
5. Прогнать весь pytest.
6. Прогнать реальный GitHub workflow.
7. Записать measured before/after.
8. Если метрика не улучшилась, зафиксировать неудачу.

### 2026-09-12: точная команда по фильтрации каналов

Исходная задача по удалению каналов состоит ровно из двух правил:

1. Убрать украинские каналы.
2. Убрать каналы из стран: Турция, Азербайджан, Венгрия, Хорватия, Армения, Греция, Румыния.

Это фильтрация выдаваемого UHF-плейлиста, а не политика поиска EPG и не общий языковой whitelist.

Текущее `data/playlist_rules.json` уже содержит обе части:
- украинские группы: `Кино UA`, `Кинозалы UA`, `Украинские`, `Українські`;
- страны: `Турция`, `Азербайджан`, `Венгрия`, `Хорватия`, `Армения`, `Греция`, `Румыния`;
- плюс отдельные украинские каналы, которые могли находиться вне этих групп, удаляются через `exclude_name_prefixes`.
